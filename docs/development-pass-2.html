A field guide to evidence, geometry, and architectural judgment

This development pass gives x3d.xray a clearer technical purpose: make a repository analysis inspectable at the point where an observation becomes a relationship, a relationship becomes a picture, and a picture becomes a claim. The result is a working synthetic Architecture Observatory, backed by real temporary Git repositories and actual Python checks. It is a bounded investigation instrument. Its strongest contribution is the explicit separation of evidence, interpretation, presentation, and interaction history.

The delivered specimen contains four repositories, 24 harvested commits, four entity glyphs, six scene polylines, and seven typed relation records. Those populations differ deliberately. A legacy association can contain several detector observations, each deserving its own predicate and grade. Scene lines still represent source associations, while the typed graph distinguishes their meanings. Treating these counts as interchangeable would erase information the architecture now preserves.

The principal implementation surfaces are prooflab.py, relations.py, scenecheck.py, scene_mutations.py, investigation.py, and the browser code in proof_web/. The existing compiler, shared tools, release gates, and receipt machinery connect this work to the production pipeline. The synthetic observatory demonstrates those connections without importing a real repository family or private material.

Read the topology before reading the picture

The pipeline branches after harvesting. On one branch, relations.build_relations() projects machine detectors and curated observations into typed records. Each record states its predicate, direction, grade, method, provided witnesses, and observation/sample counts. On the other branch, compiler.constellation_region() produces X3D geometry and a declared scene plan containing stable entity identities, intended world positions, primitive dimensions, ordered polyline points, attachment offsets, and grade colors.

scenecheck.verify_scene() independently parses the emitted XML and compares its actual static geometry with that plan and the original source-tie records. It composes transforms, resolves supported DEF/USE references, reads primitive dimensions, follows coordIndex, and checks source endpoints and grade encoding. Coordinates are read from geometry; metadata supplies semantic identity. A label repeating the intended position cannot satisfy a geometric check.

This is a meaningful independence boundary, but its scope must remain precise. The plan and scene originate in the same compiler. Agreement between them establishes conformity to the declared plan; it does not independently establish that the plan is the best interpretation of the repositories. Likewise, the checker can require a supplied source witness without proving the witness's external authenticity. Source-to-predicate interpretation, plan-to-XML correspondence, and runtime appearance are separate questions.

Receipts bind exported bytes and relevant recorded identities. The observatory's detached content receipt identifies its assets and control script and explicitly declines publisher authentication and full-family release readiness. A changed file can be detected against a retained trusted digest. An attacker able to replace both files and receipt can recompute hashes. Publisher signatures would be a separate trust mechanism, justified only when distribution or collaboration needs it.

Investigation events form another branch. They bind selections, filters, query endpoints, and requested mutations to fixture and analysis digests. Replay validates the chain and catalog before reducing intent into view state. It neither reruns the verifier nor turns a requested experiment into an executed result. This distinction allows a saved investigation to be useful without quietly becoming a fabricated laboratory notebook.

What the checks establish

The production release contract now names eight required gates. Each can pass, fail, or skip; a missing prerequisite remains visible. A diagnostic run that has no detected failure can still lack release readiness when a required gate was skipped.

Gate Concrete responsibility
xsd Validate the scene against the supplied X3D schema.
loom Run the available Loom/fork validation integration.
fact Check the narrative's structured claims, slots, and rendered specification contract.
privacy Check published build material for the defined sensitive patterns and private itemization.
witness Reconcile bundle/layout/source witnesses and recomputed analytical stages.
scene Independently inspect the emitted static constellation geometry against the declared plan and source bundle.
tools Exercise the shared data-tool and MCP interfaces within their transport contracts.
live Exercise the browser integration and its harness under the configured policy.

The new scene gate closes an important gap between checking layout metadata and checking the artifact actually emitted. It also refuses disagreement between the build-control plan and the plan served in the bundle. The witness gate and scene gate are complementary: one follows analytical provenance and membership; the other reads geometric correspondence from XML.

The live harness has its own limit. Its Ask integration uses a stand-in for the host sampling runtime. That exercises routing and integration behavior; it is not evidence that an actual hosted model session ran successfully. Static scene acceptance also does not certify pixels, navigation, fonts, lighting, visual legibility, or all X3D behaviors. The supported subset deliberately excludes other scene regions and runtime-dependent semantics.

The observatory browser displays recorded Python audit results generated at build time. Selecting a mutation chooses an embedded XML case and its actual recorded result. The browser does not execute the Python verifier. It does execute the shared architecture query tool against the unchanged typed graph. Optional X_ITE rendering provides another view of the selected artifact, while its rendered pixels remain outside the static proof.

Thirteen experiments, including the boundary

The mutation suite holds source records and plan fixed while changing XML. Its 13 cases comprise the baseline, ten adversarial changes that are rejected, an equivalent geometric transformation that is accepted, and a scope probe that is accepted within the declared subset.

The ten rejected changes move an entity, enlarge a primitive, move a used edge endpoint, reverse coordinate-index traversal, alter grade color, falsify endpoint metadata, duplicate a DEF, inject an unregistered line into the semantic relation layer, introduce an unresolved Coordinate USE, and hide the semantic layer beneath a Switch. Each targets a concrete way for a plausible-looking artifact to disagree with its recorded meaning.

The equivalent-transform case is just as important. Nested translation, rotation, and scale alter the bytes while preserving composed world geometry. Acceptance demonstrates that the checker is evaluating the supported geometric contract rather than demanding byte identity. The outside-layer case demonstrates the converse limit: adding unrelated geometry outside the semantic layers does not receive a blanket certificate merely because the instrumented subset still conforms.

One review finding exposed why resource contracts must describe realized work. A small acyclic DEF/USE graph can expand into exponentially many instances even when its XML is short and its depth is legal. The checker now shares a 250,000 expanded-visit allowance across reference resolution, the global walk, and glyph subwalks, terminating with an explicit expansion-limit finding. This is a bounded-work safeguard; it is not a throughput benchmark or a complete renderer resource policy.

Two presentation corrections reinforce the same discipline. Curated relationships project conservatively as symmetric associations, so unsupported curated arrowheads were removed from the constellation. In the optional 3D view, the already loaded case is reused across unrelated interactions, preserving camera context instead of repeatedly replacing the world. Neither correction needs spectacular effects to improve the instrument: both make it say less falsely and behave more coherently.

Six heuristics for the next architecture decisions

Challenge common-mode agreement. Independent code can still share an incorrect premise. Keep hand-authored geometric fixtures alongside compiler-produced mutation cases. Add tests where XML and plan agree on an intentionally wrong source interpretation, then verify that the separate interpretation contract detects it. Give each boundary its own counterexample instead of treating a green end-to-end result as universal proof.

Keep predicates stronger than visual suggestion. A dependency_reference is a static reference, declares_use is an attributed configuration statement, shared_session records trailer overlap, and curated_association retains a curator's association. Paths should preserve their predicate sequences and original endpoint directions. A chain of C observations does not become runtime dataflow; C/L/S are neither calibrated probabilities nor transitive path-confidence scores.

Make witnesses reconstructible. Hashing a projected evidence object establishes an identity for that object. It does not establish that its snippet was read correctly from an immutable source. Public witnesses should progressively acquire full repository revision, blob identity, path, span, detector version, and declared extraction scope. Keep private aggregates outside that locator contract; a hash of withheld private detail can itself create an unwanted stable correlation surface.

Ask when a path existed. A current import, an old session link, and an owner-stated lineage may have been observed at different times. Their coexistence in one analysis snapshot does not prove that the corresponding architectural route existed simultaneously. Introduce observation times and, where supported, validity intervals. Label unknown temporal overlap explicitly. Never infer a relationship's birth or death merely from the first or last available observation.

Count populations, then bound work. Preserve separate counts for supplied observations, returned witnesses, withheld assertions, eligible graph records, shortest node paths, and omitted presentation records. Parallel witnesses support a hop without multiplying distinct node paths. Apply budgets before expensive expansion and enumeration, and show omission counts in the interface. A small returned result can still hide an expensive computation; a capped overlay can still represent a larger checked population.

Bind replay to interpretation. Current chains bind fixture and analytical-result identities and correctly decline actor authentication. The current analysis identity includes hashes of the compiler, verifier, relation projector, event reducers and query implementation. This prevents an unchanged fixture from silently replaying against changed interpretation sources. A future cross-release protocol should add explicit compatibility and migration rules, plus environment identities where results depend on them. Preserve the distinction between an operator's intent, a computation's recorded result, and a publisher's authenticated statement.

A staged development plan with exits

The next phase should deepen one boundary at a time. First, consolidate the trust contract. Add immutable public witness locators and explicit detector versions; formalize compatibility around the implementation hashes already included in the analysis identity. Acceptance means an unchanged snapshot is reconstructible, a changed public blob or extraction method changes the relevant identity, private-detail changes do not alter the public-safe projection improperly, and Python/browser replay rejects incompatible contexts. Stop before adding author signatures or a provenance database unless a concrete collaboration workflow requires them.

Second, make typed relationships the cross-view semantic authority. Preserve legacy association geometry where useful, but map each displayed claim to its typed record and keep symmetric associations arrow-free. Acceptance means outgoing, incoming, and association queries differ where expected; unsupported detector assertions remain withheld with reason counts; visual arrows agree with predicate direction; and a mixed-predicate path is never described as executable dependency. Stop expanding the predicate vocabulary when a proposed predicate lacks a reproducible detector and a refuting fixture.

Third, measure scale separately from correctness. Generate disclosed synthetic populations at 10, 100, and 1,000 entities with controlled degree, parallel observations, disconnected components, and long identifiers. Record export bytes, verifier work counts, query work, browser load, interaction latency, memory, and renderer behavior on a stated machine and browser. Acceptance means budgets reject oversized work clearly, selection preserves the loaded scene, omitted observations remain visible, and measurements reproduce within documented environmental variation. Stop adding effects when readability or interaction deteriorates; choose partitioning, clustering, indexed lookup, or label decluttering from evidence. No city-scale or GPU-performance claim follows from the current four-node specimen.

Fourth, evaluate one real public family after these contracts stabilize. Keep the synthetic suite as the reference and document each real-data omission. Acceptance means actionable findings trace to immutable witnesses and another reviewer can reproduce selected queries and scene checks. Stop short of organization-wide ingestion until this small review produces useful, independently inspectable decisions.

Creative experiments that earn their spectacle

An evidence and refutation studio could let a reviewer place a relationship claim beside its supporting records, exclusions, and strongest counterexample. A staged mutation would show the exact boundary that fails, while equivalent transformations reveal what meaning survives. The visual drama would follow the evidence: the same object can be accepted geometrically while its architectural interpretation remains contested.

A time lens could animate relationships by observation window, with a conspicuous distinction between known overlap and unknown validity. Pinning two snapshots would expose introduced references, removed witnesses, and unchanged claims whose detector version changed. It should visualize recorded change before attempting narratives about causation or developer intent.

A scale and fidelity laboratory could compare the complete instrumented scene, clustered overview, focused neighborhood, and selected evidence trail. Its controls would disclose entity count, edge count, labels shown, records omitted, measured work, and the selected rendering policy. Beauty would become an adjustable analytical resource rather than a reason to obscure missingness.

For standards study, retain the official X3D 4.0 Grouping component reference. It is a reference for further implementation review, not evidence that this bounded checker implements the entire component. The durable opportunity is an observatory in which every compelling visual move leads naturally to an inspectable claim, an explicit limit, and a useful next experiment.
