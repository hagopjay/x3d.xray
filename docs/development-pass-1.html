A working implementation, a synthetic investigation laboratory, and a field guide to the reasoning behind them. Base source: b3fec1f7307a08a830bb82cf7693fad9537965ae. Development version: 0.2.0.dev1. Prepared November 12, 2026.

The review has become code. This pass repairs source-fidelity and publication boundaries, accelerates graph separation queries while retaining independent verification, and adds an interactive laboratory whose conclusions can be traced to explicit observations. The work remains on a local development branch; nothing was pushed or published to the upstream repository.

2. Start playing — zero to investigation

Extract the offline laboratory ZIP. On Windows, run py -3 start_lab.py; in WSL or Linux, run python3 start_lab.py. Open the printed loopback URL, normally http://localhost:8765. The server listens only on the local loopback interface. Stop it with Ctrl+C.

The standalone HTML works directly for the map and analytical controls. The offline ZIP supplies local X_ITE assets for 3D. A standalone HTML without those assets attempts the pinned CDN renderer only when 3D is selected. Rendering still depends on the browser's WebGL support; the analytical map and data do not depend on that renderer.

Begin with Start the guided investigation. It takes you through six observations:

  1. Let README.md participate and inspect its high centrality.
  2. Set the frequent hub aside and inspect evidence.py as a cross-community separator.
  3. Change only the distance from count to Jaccard.
  4. Admit the generated 16-file sweep by raising the mass-edit threshold.
  5. Remove evidence.py in a graph counterfactual and inspect the resulting components.
  6. Restore the lens, inspect a witness and save the investigation state.

Click a node to inspect its component, degree, betweenness and cut status. Click an edge to inspect the exact observations that changed both files. Click a witness to illuminate its files. The witness strip scrolls horizontally; it does not silently discard records.

The four comparison buttons change count/Jaccard and keep/prune independently. They compare the baseline observations for the selected mass-edit threshold. A removal is a separate graph experiment and is cleared when choosing one of these baseline lenses.

Save investigation stores the selected lens, node/edge and witness. Replay requires both the matching fixture digest and analytical-result digest. This is state replay; an arbitrary user-authored event storyboard is a future extension. The guided sequence is built in.

The frequent README acts as a coordination hub in the recorded history. That does not make it an executable dependency. Pruning it exposes a different topology. evidence.py becomes an articulation between ingestion and presentation; several other cuts connect leaf tests or local regions, so “cut vertex” alone does not establish architectural importance.

The second component in the pruned baseline is an isolated documentation file. This matters: a component count is a fact about the selected graph, not automatically a count of product subsystems.

At cutoff 30 with Jaccard and pruning, the graph has 15 nodes, 105 edges, one component and no cut vertices. The generated sweep has created a clique among the retained nodes. A single broad edit can erase the appearance of a bottleneck without introducing a runtime integration at all.

This fixture uses a 65% frequent-hub threshold, with a five-commit minimum, to isolate README.md. The production structure stage retains its own declared policy. The lab deliberately labels the difference instead of quietly changing the production denominator.

5. The strongest performance lesson: change the question

The original passage-point routine repeatedly asked: “If I remove this vertex, are these repositories still connected?” It did that for many vertices and repository pairs. The definition is excellent as an oracle; it repeats too much work as the main algorithm.

The new index asks: “What are the graph's biconnected blocks, and which articulation vertices connect them?” These form a forest. A required passage point lies on the unique forest path between the corresponding endpoints. Connectivity structure is built once, then reused.

The index is iterative and handles a 5,000-node test chain without recursive stack growth. It is an undirected connectivity structure: asymmetric adjacency is rejected, and edge weights do not change whether a path exists. Rebuild the index when the graph changes.

The measurements include the paired graph verifier, but exclude the rest of harvesting, profiling, scene generation and rendering. They are neither GPU benchmarks nor full-pipeline capacity promises.

The verifier was also improved, but it does not call the production block-cut index. It removes each relevant vertex once and reuses the resulting partitions. This preserves a separate route to the answer.

Heuristic: optimize the production explanation; retain the simple definition as an independent small-input oracle. Matching outputs comes before reporting speed.

A faster index cannot shrink a large explicit answer. All repository pairs still require quadratic enumeration, and all passage lists on a chain can contain cubic total output. Pair-specific queries and pagination remain useful future work. Exact weighted Brandes centrality remains another distinct cost.

6. Heuristics learned while making the pass

A display limit must not become a detector limit

The original tie grade depended on retained evidence records. One extra weak mention could push a manifest witness past the display cap and lower the result. This is a deeper invariant than a larger cap:

All observations → complete detector summary → decision → representative display.

The new sampler keeps bounded representatives and reports omissions. Late evidence can still change the decision. The principle also applies to agent context windows, search results, code excerpts and dashboards: never confuse what was shown with what was considered.

Internal identity and visible identity have different jobs

A twelve-character hash is useful in a card. It cannot validate an arbitrary forty-character token. Full Git object IDs now remain available internally during tie discovery; private commits never receive that field, and recursive export stripping removes internal fields.

A supplied full token must match in full. Abbreviations must resolve unambiguously in the observed index. This fixes a validation weakness without requiring a claim that a real collision occurred in the user's repositories.

Downstream agreement cannot repair a corrupt source join

A graph, profile and gate can recompute the same wrong answer from a path quoted differently by two Git commands. Real temporary-Git fixtures therefore sit below the analytical oracles. They exercise the actual wire representation, not a friendly hand-written dictionary that already assumes the parser was correct.

The retained boundary is explicit: arbitrary non-UTF-8 Git paths round-trip internally, but all UTF-8/JSON/XML export layers do not yet share a completed reversible display policy. Unicode and tested tab/newline/backslash paths are covered; universal filesystem-byte export is not claimed.

A release needs one definition of its bytes

The normal page builder registers the assets it emitted. Scanner, publication map and receipt consume that same set. The receipt deliberately excludes its own byte hash and attests the other served assets; this avoids an impossible self-hashing cycle.

New lab export tests caught the same class of mistake in the first lab builder: recursively collecting its output directory would have attested an unrelated stale JSON. The builder now hashes only explicitly written assets, and invalid vendor input is checked before overwriting the entrypoint. Applying an invariant to newly written examples is as important as fixing the reviewed code.

Vendor registration proves bytes remained consistent after registration. It does not authenticate the upstream package publisher. Owned-output regex scanning is a limited detector, not universal proof that text contains no sensitive information.

Normalize a serving path once

The new loopback server is tested against actual HTTP requests, including unapproved files and traversal. Independent review found an important edge case: validating an encoded name before a downstream handler decodes it again can authorize one path and serve another. The manifest now refuses ambiguous percent/URL-control characters, matching the main publication policy. An allowlist is only as precise as the path interpretation shared by its validator and file server.

A snapshot is not enough to reproduce an analysis

The saved investigation binds two identities: observations and analytical results. An unchanged specimen can yield changed answers after an algorithm or parameter policy changes. Replay now rejects a mismatched analytical-result digest as well as a mismatched fixture digest.

The broader production build still has execution timestamps and platform-dependent context. This pass does not claim identical semantic data always produces a byte-identical complete receipt across machines.

Change one factor at a time

Comparing count/all against Jaccard/pruned changes two things at once. The four-lens panel keeps those factors independent. It can tell whether a result depends on normalization, node exclusion or both.

Likewise, a mass-edit cutoff is an analytical choice. A 15-file edit produces 105 pairs; a 16-file edit can produce none at that threshold. An honest tool should reveal the cliff, retain exclusion counts and help the user test robustness.

A counterfactual belongs to a named model

Removing evidence.py changes the observed co-change graph. It does not predict whether deleting that Python file would crash an application. The lab preserves source observations and recalculates graph topology and scores. Its language stays inside that model.

A future impact-analysis tool should add directed imports, API contracts and tests as separate evidence layers before recommending source changes.

To regenerate the lab from source:

python3 -m x3dray lab --out out/bridge-lab
# Optional local renderer assets:
python3 -m x3dray lab --out out/bridge-lab --xite path/to/x_ite/dist

To use strict release policy on the normal pipeline:

python3 -m x3dray gate --data data/family --out out/family --release

The all command now uses fresh data/output stages, a shared run stamp and one self snapshot before spec rendering. On failure the prior destinations remain intact and diagnostic stages are retained. Successful promotion keeps prior destinations as named backups. This is reversible sequential promotion, not an atomic pair or protection against concurrent writers. Stop serving or mutating those directories while building.

The DOM checks exercise actual generated JavaScript: lens controls, selected relations, witness highlighting, removal/restore, guided sweep admission, save-state identities, X3D export and replay rejection. They do not measure pixel layout or execute WebGL.

The exported lab scene was validated against the downloaded official X3D 4.0 XSD and its dependencies. Its metadata includes source/analysis identity and edge witness IDs. Schema validity is useful, but remains a different statement from seeing correct pixels in X_ITE.

The prepared CI matrix targets Python 3.10/3.12 and Node 24. Remote CI was not run in this session. Packaging was built locally and the wheel contains both the normal web assets and laboratory templates.

No full private-family harvest, complete external Loom integration, real host sampling runtime, or hardware GPU benchmark was performed. The local preview browser could not reach the execution host's served app, so visual/runtime graphics verification remains a concrete next check on the user's Windows/WSL browser.

9. The next bounded iterations

Next A — independently verified scene semantics. Parse the actual scene into entity/relation records and compare endpoints, grades, metadata and picking IDs against a renderer-neutral scene plan. Keep this verifier separate from the compiler. Mutation tests should alter scene geometry while leaving layout records unchanged.

Next B — typed architecture traversal. Introduce directed imports/uses/pins alongside symmetric shared-source and co-change relations. Add predicate/direction filters and evidence-bound paths. Preserve the current association graph as a useful separate question.

Next C — portable exhibition themes and accessible selection. Extract repository anchors, names, author labels and cameras into a family theme. Make one selection store serve the 3D scene, a keyboard-operated list and exact tables. The normal exhibition still contains family-specific assumptions; this pass adds an independent synthetic lab rather than claiming those assumptions are gone.

Next D — runtime and scale evidence. Verify X_ITE scene load, selection and cancellation on the target browser. Record renderer/driver, viewport, DPR, dataset digest, frame-time distribution and interaction latency. Keep functional software-renderer checks separate from GPU performance. Then profile streaming logs, batch blob reads, exact centrality and pair-output size before choosing further acceleration.

Next E — evidence-backed capability discovery. Add a small files × capabilities context for X3D validation, conversion, materials, animation, splats and provenance. Distinguish declared, implemented, tested and runtime-verified support. Each attribute should have an extractable witness; a model can propose hypotheses, but should not silently become the source of a factual capability label.

The practical north star is an investigation a reviewer can reproduce: source observation → explicit analytical choice → computed result → visual selection → inspectable witness → saved explanation.

Local development only; no upstream push. Benchmark and validation scopes are explicit. Full host/X_ITE/GPU runtime verification remains a separate check.
